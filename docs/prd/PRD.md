# PRD.md — 股票交易正規化、FIFO 配對與報表系統

> 專案：`trading_report`  
> 文件版本：v2.0（全新設計，不沿用前版 Excel 直接填表架構）  
> 日期：2026-11-20  
> 需求優先順序：P0 必要、P1 後續擴充  
> 執行環境：Windows 10/11、Cursor Agent、Python 3.11+  
> 原則：**本機資料庫、免費／開源、原始交易不變、交易明細與統計分離**。

## 1. 產品定位

開發全新的本機股票交易資料系統：接收券商交易紀錄（買進／賣出），先辨識格式並正規化，寫入 SQLite 資料庫；以資料庫為唯一的交易事實來源，執行同股票／同帳戶的 FIFO 買賣配對；最後參考使用者既有股票紀錄表的**欄位順序與明細呈現方式**產生 `.xlsx` 報表。

**不再使用舊 Excel 彙整表作為交易儲存、FIFO 狀態或新增交易的依據。** 原 Excel 僅是報表欄位／顯示格式的參考。統計、加總、績效分析須由獨立的報表流程產生，**不得在明細資料表最後附加合計列、小計列或任何不同型別的資料列**。

```text
券商 CSV／XLS／XLSX → 格式偵測 → 解析與欄位映射 → 正規化與驗證
                                               ↓
                                   SQLite（本機原始＋標準交易）
                                               ↓
                                     FIFO 配對（版本化）
                                               ↓
                                    明細報表 XLSX（純明細列）
                                               └── 獨立統計報表（P1）
```

## 3. 使用者與主要情境

**使用者**：本機持有不同券商交易匯出檔，想統一管理買賣、追蹤未結清部位、產生既有格式的對帳明細。

**正常流程**：
1. 選擇一個或多個 `.csv`、`.xls`、`.xlsx` 交易檔；指定券商與交易帳戶。
2. 系統辨識格式、預覽欄位映射、交易數量、資料品質與重複風險。
3. 原始檔案保留不變；原始列與正規化交易一併入庫。
4. 使用者確認例外後，以 FIFO 計算買賣配對，將配對結果獨立保存。
5. 輸出交易明細 Excel（欄位參考舊紀錄表），每一列皆為明細，**沒有末列合計**。
6. 如需持倉、已實現損益、期間統計，另行產生**獨立統計報表**（P1）。

## 4. 核心設計原則

- **資料唯一來源**：SQLite 中經驗證的交易紀錄；Excel 為可重建的結果，不是來源。
- **資料正規化**：不同券商用 mapping profile 對應共同欄位；來源欄位、原值、原列號保留供稽核。
- **原始交易不可因拆單修改**：一筆交易在交易表始終只有一筆；拆單僅反映在 FIFO 配對表與報表投影。
- **同型別資料列**：明細工作表只允許欄名＋明細列；不寫小計、總計、說明、統計或空白分隔行到資料區。
- **費用不拆分**：手續費、交易稅與其他實際費用保留在原始交易；明細展開時，同一來源費用只出現一次，固定落在該來源交易的第一個輸出片段。
- **不得假設缺漏資訊**：買進時間、期初庫存、券商帳戶、融資交易規則不明時，阻擋或列待確認，不猜測。
- **可追溯、可重跑**：每筆交易→來源列、每筆配對→原始買／賣、每份報表→交易集合＋配對執行版本。
- **離線與免付費**：本機 SQLite，不需遠端伺服器、付費 API、Microsoft Excel 授權或雲端帳號。

## 5. 功能需求

### FR-01：格式辨識與多檔匯入（P0）
- 支援 `.csv`、真正的二進位 `.xls`、HTML 偽 `.xls`、`.xlsx`，依檔案內容與簽章判斷實際格式。
- CSV 支援 UTF-8、UTF-8-SIG、Big5/CP950；無法可靠解碼時應提示使用者指定編碼，不得默默替代字元。
- 適用多檔、多券商、不同欄名與順序；透過可設定的 mapping profile 正規化。
- 排除空列、說明列及總合列；記錄被排除與拒絕的原因、列號。
- 同檔重複上傳：同帳戶不重複入帳；不同檔包含疑似相同交易：列出衝突，**不得僅以日期／代號／價格／股數相同就自行刪除**。

### FR-02：標準化與驗證（P0）
- 每筆交易至少有：券商、帳戶、來源、成交日期、股票代號（文字型別）、買賣別、幣別、成交股數、單價、成交總額、實際手續費、交易稅。
- 額外保留：來源名稱、成交時分秒（若有）、來源交易序號／成交編號（若有）、利息及其他費用、股票名稱、原始欄位 JSON。
- 買賣別統一為 `BUY` / `SELL`，日期為 ISO 格式；股數必須為正整數；金額／價格採十進位精確計算，不使用二進位浮點數。
- 原始交易金額、成交價×股數、淨收付間差異須可檢查；不可將不合理差異靜默修正。
- 初期只自動處理**已識別的台灣現股買進／賣出**；融資、融券、當沖、拆股、配股等未定義情境先列例外。

### FR-03：SQLite 交易儲存（P0）
- 資料庫位於使用者本機，預設 `data/trading.db`，可由 CLI 指定其他本機路徑。
- 保存交易原值（raw）、標準化交易（canonical）、帳戶、匯入批次、例外及配對、報表執行紀錄。
- 匯入交易要採資料庫交易（transaction）：成功提交、失敗回滾；同一批重跑不重複新增。
- 來源檔可另存到私有的本機封存資料夾，與資料庫的 SHA-256 對應；不得自動上傳 GitHub／雲端。
- 提供資料庫備份、基本完整性檢查及 schema migration。

### FR-04：FIFO 買賣配對（P0）
- 以「**帳戶＋股票代號＋幣別＋相容交易類別**」分組，買進依確定的成交先後形成持倉批次（lot）。
- 賣出先配對時間最早、尚有剩餘數量的買進；完全結清則向下一買進續配。
- 支援一買對多賣、一賣對多買、部分賣出、未結清買進；買賣量必須守恆。
- **不得把賣出配對到未來買進**。若同日買賣缺少足以判定先後的資訊且影響結果，列待確認。
- 期初已有持股、但缺少原始買進時：先產生缺少歷史庫存例外；日後可透過明確匯入／核准的 `opening_lots` 補正，不得虛構買價。
- FIFO 配對儲存在獨立的版本化結果資料表，重算不改寫原始交易。

### FR-05：費用與計算（P0）
- 原始交易的手續費、交易稅、利息等保留原金額，**不按股數比例分攤費用**。
- 展開報表時，同一買進交易的費用只放在它的**第一個買進片段**；同一賣出交易的費用只放在它的**第一個賣出配對片段**，其他片段費用為數值 `0`。
- 配對片段的成交總額／成本／收入按數量及價格計算，必要的金額尾差有固定、可重現的處理規則；**成交總額的數學拆算不等同分攤手續費或稅費**。
- 成本、收入、已實現損益在程式計算，明細中數值欄必須是真正的 Excel 數值型別。未結清列的賣出欄位及已實現損益用空值，不可用文字 `-` 或 `未賣出` 填入數值欄。
- 不因舊 Excel 的公式錯誤影響新資料；價格、股數、日期、損益、報酬率等欄位均按資料字典輸出。

### FR-06：交易明細報表（P0）
- 產生 `.xlsx`，欄位先對照原紀錄表 **A～W 23 欄**；報表資料區只含明細。
- 一列代表「買進與賣出配對片段」或「尚未賣出的買進片段」；買進／賣出股數互相對應，未配對賣出另外列在例外資料，而非假造買進列。
- 所有資料列須依欄位固定型別：日期為日期、股數為數值、價格與金額為數值、股票代碼與券商為文字、未提供值為空白。
- **嚴禁底部合計列、底部備註列、混合型別的小計／統計列**；也不把統計資訊插在明細工作表上方。
- 可使用篩選、凍結表頭、適當數字格式；統計／稽核資訊須輸出至**獨立檔案**而非明細表格內。
- 舊紀錄表只參考欄位與呈現，不依賴原工作表的共享公式；系統自行生成乾淨報表。可在將來提供「公式版」選項，但不得破壞型別契約。
- 名稱含時間戳：`交易明細_YYYY-MM-DD_HH-mm-ss.xlsx`；原始檔不能覆寫，若檔名碰撞自動加流水號。

### FR-07：獨立統計報表（P1）
- 使用相同 SQLite 交易資料與 FIFO 執行版本產生另一份報表，例如 `交易統計_YYYY-MM-DD_HH-mm-ss.xlsx`。
- 可按券商、帳戶、股票、年度、期間統計買賣金額、剩餘股數、已實現損益、費用等；跨幣別不得無匯率就直接加總。
- **不在交易明細的最後一列加總**。統計報表可有自己的彙總表、圖表與 KPI，但不可混入交易明細資料集。

### FR-08：稽核、例外與重複匯入（P0）
- 提供來源檔雜湊、批次 ID、原列號、正規化狀態、交易 ID、FIFO 配對 ID 的查核鏈。
- 來源買進數量 = 已配對買進數量＋未售數量；來源賣出數量 = 已配對賣出數量＋未配對數量。
- 各來源交易費用在展開報表後合計出現一次；不重覆、不無故遺漏。
- 有缺少期初持倉、同日次序歧義、負股數、價金不符或未支援類型時，產生 `exceptions.csv` 或 `audit.json`，包含完整來源定位。
- 預設有阻擋性例外不產生「已核對完成」正式版；可用 `--allow-partial` 產生標示 `DRAFT` 的明細報表及完整例外報告。

### FR-09：本機 CLI（P0）與可選介面（P1）
- `db init`、`import preview`、`import apply`、`match fifo`、`report detail`、`audit`、`db backup` 等 CLI 子命令。
- CLI 可指定券商、帳戶、mapping profile、資料庫路徑、來源檔、日期區間、輸出資料夾、dry-run。
- 第二階段可使用免費本機 Streamlit 介面；**V1 無需 FastAPI、React、Docker、PostgreSQL 或遠端服務**。

| B | 賣出日期 | 日期／空 | 已配對賣出日；未賣出留空 |
| C | 股票代號 | 文字 | 股票代號（保留前導零） |
| D | 商品名稱 | 文字／空 | 來源名稱 |

| I | 賣價 | 數值／空 | 已配對賣出單價 |
| J | 股數（賣） | 整數／空 | 已配對片段股數；未賣出留空 |

| L | 交易稅 | 數值／空 | 賣出交易稅第一次出現時填入 |
| M | 利息 | 數值／空 | 若來源有且已支援該交易類型才帶入 |
| N | 融資金額 | 數值／空 | 未支援融資時留空，不虛構 |
| O | 融資年息 | 數值／空 | 未支援融資時留空，不虛構 |
| P | 成本 | 數值 | 本片段買入價金＋應歸屬此列的一次性買費 |

| R | 損益 | 數值／空 | Q − P；未賣出留空 |

## 7. FIFO 與費用範例

買進 B1：1,000 股、買手續費 20；買進 B2：500 股、買手續費 10。賣出 S1：1,200 股、賣手續費 18、交易稅 36。

配對：B1→S1 1,000；B2→S1 200；B2 留存 300。

- B1 的買費 `20` 在 B1 第一次輸出片段；B2 的買費 `10` 在 B2 第一次輸出片段；B2 未賣片段買費 `0`。
- S1 的賣費 `18`、稅 `36` 只在 S1 的第一筆配對片段；第二片段均為 `0`。
- 源資料中 B1、B2、S1 各保留**一筆未拆的交易**；只有配對與報表有多片段。
- 若出現買進早於本批資料的賣出而缺少先前買進，須先記錄缺額，不得將未來買進倒填。

## 8. 非功能性需求

| ID | 要求／驗收方式 |
|---|---|
| NFR-01 | 完全本機離線可用；不需任何付費 API 或資料庫服務 |
| NFR-02 | 任何原始檔讀取前後 SHA-256 不變；入庫不修改來源 |
| NFR-03 | `Decimal` 運算，股數整數；誤差及尾差規則可測試、可追溯 |
| NFR-04 | 資料庫啟用外鍵；關鍵流程採 ACID 交易，失敗回滾 |
| NFR-05 | DB、券商原檔、輸出報表、備份、個人憑證不納入 Git |
| NFR-06 | 同一組交易、同一排序規則、同一演算法版本，可重現相同配對 |
| NFR-07 | Excel 明細每一列符合固定型別；沒有合計列、文字形式數值與偽日期 |
| NFR-08 | 錯誤與例外定位到來源檔、工作表、列號、欄位與原因 |
| NFR-09 | 不直接覆寫已產生的報表；資料庫須可備份與驗證復原 |
| NFR-10 | 匯出採暫存檔→驗證→安全重新命名；錯誤不得宣告成功 |

## 9. V1 驗收案例（必須有 pytest／端到端測試）

1. `Statement (2).xls` 正確辨識為 HTML 表格，得到 65 筆有效交易（22 BUY、43 SELL），兩筆總合列不入庫。
2. 同一檔案、同一帳戶重複匯入不產生新交易；其他檔的相似成交列出待查而非擅自刪除。
3. 一買多賣、一賣多買、部分賣出、未售尾數、完整結清結果及總股數守恆。
4. 來源手續費與交易稅在每筆交易各只出現一次，總額守恆；費用不是按數量分攤。
5. 賣出早於所有已知買進時報缺少期初庫存，不配對未來買進。
6. 同一天成交但無法判定先後，且會影響 FIFO 結果時產生待確認狀態。
7. 無相容帳戶或無同股票代號時，不跨帳戶或不同股票配對。
8. 每次輸出明細 `.xlsx`：**僅一列表頭＋全部明細列，沒有末列小計／總計**；A～W 型別檢查通過。
9. 空值是真正空白，買賣價格／股數／金額為數值，日期為 Excel 日期；股票代號為文字。
10. 在不安裝 Microsoft Excel、不連網下可完成解析、入庫、FIFO、Excel 報表輸出與稽核。
11. `--allow-partial` 只能產生 `DRAFT` 報表並附例外；預設阻擋性例外不得顯示對帳已完成。
12. 原始交易與匯入／配對／報表均有可追溯的識別碼；備份恢復後筆數與雜湊核對成功。

## 10. 實作優先順序

- **P0 / Milestone 1 — 資料層**：原始檔格式偵測、券商 mapping profile、正規化、SQLite schema、去重及驗證。
- **P0 / Milestone 2 — 配對層**：Opening lots 政策、FIFO 演算法、費用一次性落點、完整稽核與例外管理。
- **P0 / Milestone 3 — 報表層**：按舊紀錄表 23 欄產生**純明細 XLSX**，型別驗證、無總計列、CLI 與完整測試。
- **P1 — 統計層與介面**：獨立統計報表、Streamlit 本機介面、更多券商 profile。

## 11. 未確認的業務決策（Agent 不得自行假定）

1. 只有成交日期而缺時間時，同日買賣如何判定成交順序？**預設影響結果則阻擋，等待交易序號或人工核准。**
2. 期初持倉的來源、成本基礎如何確認？**預設不得從舊彙總表猜測買價或來源成交。**
3. 帳戶與跨券商移轉規則？**預設不得跨帳戶 FIFO。**
4. `實際報酬率`、`大盤連動性` 原先的明確算法？**預設留空，不臆測。**
5. 其他交易類型、股數單位（股／張）、手續費折抵、特殊稅費？**預設只支援明確可辨識的現股。**
6. 如同一檔不同匯入檔重複包含實際相同成交，需依來源交易 ID 或人工核准建立合併關係。

## 12. V1 不做的事

- 不從舊版 Excel 讀取「目前庫存」作為正式交易資料；僅借用報表欄位與風格。
- 不沿用舊版直接寫入 Excel 的程序、公式和統計總計列。
- 不自動接券商 API、即時下單、匯率換算、稅務申報、短線策略、融資融券、股利及公司行動。
- 不建置公網服務、不上傳交易資料到雲端、不使用付費套件。
