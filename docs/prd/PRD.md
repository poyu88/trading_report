# PRD — 股票交易對帳單自動整理系統

> 專案代號：`trading_report`  
> 文件版本：v1.0（需求基準稿）  
> 文件日期：2026-11-20  
> 目標環境：Windows 10/11、Cursor Agent、Python 3.11+  
> 授權與成本原則：**執行端優先使用免費、開源套件，不依賴付費 API、雲端資料庫或商業軟體授權。**

## 1. 專案概述

建立一套可從券商逐日交易紀錄（`.csv`、真正的 `.xls`、HTML 偽裝的 `.xls`、`.xlsx`）匯入資料，依 **FIFO（先進先出）** 規則，將交易填入使用者提供的既有 Excel 彙整紀錄表，並另存為帶時間戳記的 `.xlsx` 新檔。

本專案的核心價值是 **可靠對帳、保留 Excel 公式與格式、可稽核、可重複執行而不重複入帳**，不是重新製作一份沒有原始公式的報表。

## 3. 使用者與使用情境

**主要使用者**：持有台灣股票交易紀錄、以 Excel 維護個人股票買賣明細的使用者。

**典型流程**：

1. 指定一個或多個逐日交易檔案（支援不同格式）。
2. 指定原始的股票彙整 Excel 範本（或上次已輸出的最新版）。
3. 指定券商/帳戶、目標工作表及必要的欄位映射。
4. 預覽輸入有效筆數、買賣筆數、重複/異常資料及預計拆分數量。
5. 執行 FIFO 比對、填表和公式檢查。
6. 查看未配對賣出、數量差異、公式驗證與輸出位置。
7. 下載或開啟新檔；原始檔保持不變。

## 5. 功能需求

### FR-01：多來源匯入與檔案辨識（P0）

- 支援單檔和多檔批次匯入；來源包含 `.csv`、`.xls`、`.xlsx`。
- 以檔案簽章與內容偵測實際型態：文字 CSV、HTML 表格、OLE `.xls`、ZIP/XML `.xlsx`，不能只看副檔名。
- CSV 支援 UTF-8 / UTF-8 BOM / 常見繁體中文編碼，編碼不可判定時回報錯誤或要求人工指定，**不可靜默替換亂碼**。
- 排除標題列、空列、總合列、說明文字；記錄原始列號與來源檔。
- 解析商品欄位中的股票代號與名稱（如 `3260 威剛`），股票代號必須以 **字串** 儲存。
- 保留來源原始值，並轉換出統一的標準化欄位。
- 第一階段支援台灣現股買進/賣出；融資、融券、現沖及其他交易模式，若無已確認規則則轉入例外清單，不得假裝成功配對。

### FR-02：彙整表載入與範本保護（P0）

- 使用者指定現有 `.xlsx`，並指定目標 Sheet（初始範本為 `股票_2025`）。
- 讀入既有買進/賣出資料，推導可用持倉與已配對股數；不得將已結清數量再次出售。
- 保留原始工作表、欄寬、儲存格格式、數字格式、原有公式與非交易資料。
- 新增資料或拆分既有買進列時，需維持列間參照及合計公式的正確性；若驗證失敗，**不得交付為成功結果**。
- 不直接更改原始範本；寫出前建立工作副本，產出全新的 `.xlsx`。

### FR-03：買進交易處理（P0）

- 有效的新買進紀錄全部納入配對來源，保留成交日、代號、名稱、類別、買價、買進股數與來源手續費。
- 同一買進可在結果表中拆為多列，每列代表已配對賣出的一個片段或尚未出售片段。
- 買進拆列時：**僅股數依配對結果拆分**，價格、代號、買進日期及其他不需按股數分攤的原始欄位沿用；買進手續費、其他原始固定費用僅記在「第一筆拆分列」，其他拆分列相關費用填 0 或不產生費用，絕不重複。
- 不能因分拆重複計算來源買進手續費。

### FR-04：賣出 FIFO 配對（P0）

- 對每筆有效賣出，從**時間最早且仍有剩餘股數**的買進開始；若已完全結清，繼續下一筆。
- 一筆賣出若小於買進剩餘量，拆出已售部分與未售部分。
- 一筆賣出若大於買進剩餘量，先結清該買進，再把賣出剩餘量匹配後續有效買進。
- 同一筆賣出可以分攤股數到多個買進批次，但該筆賣出手續費與交易稅等**各僅記錄一次**（預設記於賣出配對的第一列）。
- 股票代號、券商/帳戶、幣別與相容交易類型必須一致；不能跨股票或不同帳戶配對。
- **不得配對至成交日晚於賣出的買進**；當同一天資料缺少成交時間而順序不明時，應列入待確認或採經使用者核准的排序政策。
- 當可用買進股數不足，賣出未配對部分列為「異常／待確認」，不虛構買進紀錄，不輸出看似完整的配對結果。

### FR-05：費用、金額與公式（P0）

- 直接使用來源提供的實際手續費、交易稅等金額；不得自行用固定費率覆寫實際成交費用。
- 需要分段的成交金額與成本，可依數量、成交價格及券商原始成交總額核對；如有捨入差異，使用可重現的尾差規則，使總額守恆。
- **只拆數量，不拆原始手續費與稅費。** 各筆交易的費用總和必須等於來源金額且不能超過一次。
- 結果表中既有 `成本`、`收入`、`損益`、`獲利率` 等計算欄盡量沿用相應公式，不將公式全數轉成固定數值。
- 輸出時驗證合計列公式、工作表參照、錯誤公式及數值守恆；未經驗證不可宣稱「公式完全保留」。
- 即時讀取公式運算後數值並非本階段必備；若需 Excel 重新計算，可於開啟 Excel 時更新，但不能依賴付費 Excel 才能完成核心流程。

### FR-06：重複匯入防護與稽核（P0）

- 每次匯入需記錄檔案 SHA-256、來源檔名、原始列號、正規化交易欄位及匯入結果。
- 同一來源重複匯入時自動跳過；不同檔案中出現極相似交易，不得僅憑「日期、股票、股數相同」就武斷刪除，應提示重疊資料風險供核對。
- 每筆買進/賣出與其拆分列須可追溯至來源紀錄和對應配對批次。
- 保留獨立的 JSON 執行紀錄/稽核清單，記錄警告、跳過、未配對、公式變更、輸入與輸出檔案雜湊。
- 若沿用「上次輸出 Excel」卻缺少相應匯入紀錄，須提示可能重複並限制自動增量執行。

### FR-07：輸出（P0）

- 輸出格式固定 `.xlsx`，預設名稱 `股票對帳單_YYYY-MM-DD_HH-mm-ss.xlsx`，以執行電腦本地時間（預期台灣時間）產生。
- 保留原始輸入與彙整範本；不得同名覆寫既有輸出。
- 提供執行摘要：有效買進／賣出筆數、跳過數、拆分列數、完全配對數、未配對數量、費用／股數核對、公式驗證結果。
- 配套儲存 `..._audit.json`（可以另外附 `..._exceptions.csv`）。
- 預設有阻擋條件時不輸出正式完成檔；可輸出明確標示 `DRAFT` 的檢查版本，但絕不標記為對帳完成。

### FR-08：操作方式（P0 / P1）

- **P0**：提供 Windows PowerShell / CMD 可執行的本機 CLI，支援 `--transactions`、`--summary`、`--sheet`、`--account`、`--output-dir`、`--dry-run` 等參數。
- **P1**：提供免費、開源的 Streamlit 本機介面，支援上傳檔案、預覽差異及下載結果。
- P0 不要求網路、不要求 GitHub Token，不需要 PostgreSQL、Docker、FastAPI 或雲端平台。

## 6. 核心業務規則與範例

### 6.1 FIFO 範例

假設同股票、同帳戶：

| 日期 | 交易 | 股數 | 註記 |
| --- | --- | ---: | --- |
| D1 | 買進 A | 1,000 | 最早買進 |
| D2 | 買進 B | 500 | 第二筆買進 |
| D3 | 賣出 S1 | 400 | 先從 A 配對 |
| D4 | 賣出 S2 | 900 | 先用 A 剩餘 600，再用 B 300 |

結果為 A→S1 400、A→S2 600、B→S2 300，以及 B 未售 200；配對賣出合計 1,300，未售 200。

### 6.2 費用範例

若 A 買進手續費為 20 元：A 的**第一筆拆分列**記 20 元，A 其他拆分列記 0 元；不得記 8+12 元，也不得兩列都記 20 元。

若 S2 賣出手續費 15 元、交易稅 27 元：S2 的**第一筆配對列**記 15 / 27 元，第二筆配對列記 0 / 0 元。收入及損益公式必須反映費用僅計入一次。

### 6.3 不得配對未來買進

如 2025-10-03 賣出某股票，輸入交易檔只提供 2025-10-20 的買進，但彙整表中無更早、未結清買進：應列為「缺少歷史持倉」，**不可用 10/20 的買進去沖抵 10/03 的賣出**。

## 10. 待確認的業務決策（未確認不得擅自推定）

1. **同日買賣排序**：來源只有日期，沒有時分秒。預設對需要同日買進才能配對的賣出列為待確認；是否允許按來源列順序、或由使用者提供時序？
2. **券商/帳戶**：交易來源沒有明確帳戶欄，彙整表有「券商」。每次匯入必須指定帳戶，避免跨帳戶 FIFO；是否有多券商？
3. **存量來源與重複交易**：既有彙整表可能含本批匯入交易；需要首次匯入的重疊區間確認，不能僅依檔名判斷。
4. **費用放置順序**：本需求確定買進拆分的費用保留於第一列；對一筆賣出拆成多列，暫定費用也只保留在第一筆配對列，待確認。
5. **交易類型**：現股以外（現股當沖、融資融券、權證、ETF 等）是否要納入？V1 預設只允許已確認支援的現股規則。
6. **2026 年交易的目標 Sheet**：是否仍寫入 `股票_2025`，或按年新增工作表？V1 由參數明確指定，絕不自動猜測。
7. **金額捨入政策**：來源成交金額與價×量可能差 0.5/1 元，應保存券商原始成交金額為總額基準；分段尾差配置與幣別小數位需核准。
